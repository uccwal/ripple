# 시연 대본 (본선 발표 10분 중 시연 4분 · 시연 영상용)

준비: `.env`에 키 설정, 수집기 실행 완료(`synthetic_data=false`), 데모 시나리오 3개를 미리 한 번씩 실행해 둔다(캐시). 브라우저 1440px, 실행 이력 비우지 않는다.

## 0. 문제 한 줄 (10초)

"정책 발표가 나오면 '우리 포트폴리오에 얼마나 영향이 있나'를 답하는 데 하루가 걸립니다. RIPPLE은 이 질문에 20초 안에, 근거가 붙은 숫자로 답합니다."

## 1. 이벤트 대시보드 S1 (30초)

- 오늘 수집된 정책 이벤트 카드. 국가·유형 필터를 한 번 바꿔 보여준다.
- "미국 반도체 수입품 관세 25%" 카드의 **분석하기** 클릭.

## 2. 새 분석 S2 (20초)

- 입구 "정책 이벤트로 시작" 선택됨, 포트폴리오 A, 20영업일. **분석 시작**.

## 3. 분석 워크스페이스 S3 — 실행 과정 (60초)

- 좌측 타임라인에서 Agent 7개가 순서대로 켜지는 것을 보여준다. "각 단계의 입력·출력·소요 시간이 기록됩니다."
- Validator가 **반려**하면 Impact Mapper로 되돌아가는 화살표를 가리킨다: "검증기가 근거 없는 확신도를 반려했고, 매퍼가 재추론합니다. 이것이 단순 LLM 호출과 다른 지점입니다." (반려가 안 일어나면 미리 실행해 둔 이력에서 반려 사례를 연다.)
- 완료 토스트 "분석 완료 · 검증 통과".

## 4. 결과 읽기 (60초)

- 요약 바: 예상 손익 −3.8% (−1,240억 원), 범위, 검증 배지.
- **숫자를 클릭** → 계산 근거 패널 S5: 수식, 팩터별 β·충격값·기여, 데이터 출처와 수집일, 계산 ID. "화면의 모든 숫자는 이 패널로 이어집니다. LLM이 만든 숫자는 하나도 없습니다."
- 탭 ① 파급 경로: 노드 클릭 → 근거 목록. 점선 = 근거 불충분.
- 탭 ③ 결과: 팩터 모델 추정 vs 과거 유사 국면 추정 나란히. 유사 국면 표의 실제 손익.

## 5. 시나리오 수정 → 재계산 (30초)

- 탭 ② 시나리오: 원/달러 충격 5% → 8%로 수정. 행이 노랗게, 과거 최대 대비 막대 이동. **재계산**.
- 타임라인 4~7단계만 다시 진행. 결과 탭의 손익이 바뀐다.

## 6. 보고서 (20초)

- 탭 ④ 보고서: 요약·경로·손익·헤지 제안·출처. "헤지 제안은 규칙 엔진의 결과이고 LLM은 문장만 다듬었습니다." PDF 다운로드 클릭.

## 7. 과거 사례 재현 (30초, 발표 자료 슬라이드로 대체 가능)

- 실행 이력에서 2019-07-01 기준 일본 수출규제 실행을 연다. "결정일 이후 데이터를 차단하고 돌린 결과와 실제 20영업일 움직임을 비교했습니다." 방향 적중률 수치 제시.

## 질의응답 대비 (예상 질문)

| 질문 | 답 |
| --- | --- |
| LLM이 숫자를 지어낼 가능성은? | 보고서는 `{{키}}` 자리표시자만 허용하고 엔진이 치환한다. 마커 밖 숫자는 Validator가 찾아 문장을 제거하고 경고를 남긴다. 계산 로그에 코드 해시가 남는다. |
| 팩터 모델의 한계는? | 선형·과거 베타 가정. 그래서 과거 유사 국면의 실제 손익을 함께 보여주고, 범위(표준오차)를 표시한다. |
| 데이터 저작권은? | 공공 API(FRED, ECOS, 공공데이터포털, Federal Register, 정책브리핑)만 쓰고 출처·수집일·라이선스를 `series.license`와 화면에 기록한다. 제3자 지수는 ETF로 대체. |
| 실제 운용에 쓰려면? | 포트폴리오 테이블에 실제 보유내역, 팩터 카탈로그 확장(신용 스프레드, 섹터 지수), 수집기 추가. 구조는 그대로. |
| 비용은? | Haiku 5.5 기준 분석 1회 약 2만 토큰 → 수 원 수준. 프롬프트에 시계열 원본 대신 요약 통계만 넣는다. |
