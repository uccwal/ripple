# RIPPLE — 정책 파급 스트레스 테스트 Agent

예선 기획서 원고 (제공 양식 pptx의 7개 필수 페이지 순서. 페이지당 분량은 슬라이드 1장 기준으로 잡았고, 각 페이지의 "시각 자료" 줄은 양식에 넣을 그림·표를 뜻한다.)

---

## 1. Summary

**한 줄**: 정책 발표(관세·금리·규제)가 포트폴리오에 미치는 영향을 Agent 7개가 **경로 → 시나리오 → 손익 → 보고서**로 20초 안에 만들고, 화면의 모든 숫자를 계산 근거로 되짚을 수 있게 하는 스트레스 테스트 Agent.

| 항목 | 내용 |
| --- | --- |
| 문제 | 정책 발표 직후 "우리 포트폴리오에 얼마나?"를 답하려면 리서치·리스크·운용이 반나절~하루를 쓴다. 답은 사람마다 다르고 근거가 남지 않는다. |
| 서비스 | 정책 이벤트 자동 수집 → 파급 경로 추론 → 팩터 충격값 → 두 가지 손익 추정(팩터 모델 · 과거 유사 국면) → 규칙 기반 헤지 제안 → 보고서. 충격값을 고치면 즉시 재계산. |
| Agent | LangGraph 공유 상태 위에 Event Analyst · Impact Mapper · Scenario Builder · Regime Finder · Risk Engine · Validator · Report Writer. Validator가 근거 없는 추론을 **반려**하면 해당 Agent가 재추론한다. |
| 차별점 | ① LLM은 숫자를 만들지 않는다 — 계산은 격리된 Risk Engine만, 보고서 수치는 계산 로그 키를 인용해야만 통과. ② 모든 수치 클릭 → 수식·입력값·출처·수집일·코드 해시. ③ Agent가 일하는 과정(입력·출력·반려·재시도)이 실시간 타임라인으로 보인다. |
| 데이터 | FRED · 한국은행 ECOS · 공공데이터포털(금융위 시세) · Federal Register · 대한민국 정책브리핑. 전부 공개 API, 출처·수집일·라이선스를 DB와 화면에 기록. 제3자 저작권 지수는 국내 상장 ETF로 대체. |
| 현재 상태 | 백엔드(Agent 7개·엔진·API·SSE)와 화면 6개 MVP가 **이미 동작**하며 테스트 28개 통과. 본선에서는 실데이터 적재, 모델 튜닝, 과거 사례 재현도 측정에 집중한다. |
| 기대 효과 | 분석 소요 시간 반나절 → 1분 이내, 분석 재현성(같은 입력 → 같은 계산 ID), 근거 추적 100%(수치당 출처 연결). 과거 사례(2019 일본 수출규제, 2025 미국 상호관세) 재현도로 검증. |

시각 자료: 4계층 아키텍처 그림(프론트엔드 → API → LangGraph Orchestrator → 저장소·LLM·Risk Engine) + 화면 S3 캡처 1장.

## 2. 문제 정의

### 현장의 질문

> "미국이 반도체 관세 25%를 발표했다. 우리 포트폴리오 손익은, 어떤 경로로, 얼마나?"

기관 운용에서 이 질문은 **발표 당일 안에** 답해야 하지만 실제로는 다음 과정을 거친다.

| 단계 | 담당 | 소요 | 문제 |
| --- | --- | --- | --- |
| 발표 원문 확인·요약 | 리서치 | 1~2시간 | 출처가 여러 곳(관보, 보도자료, 뉴스), 수치 정리 수작업 |
| 파급 경로 정리 (산업 → 환율·금리·업종) | 리서치 | 2~3시간 | 사람마다 다른 경로, 근거가 메모로만 남음 |
| 충격 시나리오 수치화 | 리스크 | 1~2시간 | "환율 +5%"의 근거가 감에 의존 |
| 포트폴리오 손익 계산 | 리스크 | 1~2시간 | 스프레드시트, 재현 어려움 |
| 보고서 작성 | 운용 | 1시간 | 숫자 복사 과정에서 오류 |

**합계 반나절~하루.** 그리고 이 흐름의 결과물은 "그때 그 사람이 쓴 문서"로 남아, 다음 발표 때 다시 처음부터 한다.

### 실제 사례 (기획서가 재현 검증에 쓰는 사례)

- **2019-07-01 일본 반도체·디스플레이 소재 수출규제** — 발표 다음 거래일 코스피 −2.2%(7/8), 반도체 업종 급락. 영향 범위를 정리하는 데 시장은 이미 움직였다.
- **2025-04-03 미국 상호관세(한국 25%)** — 원/달러 4/9 1,484원까지 급등. 환율·수출주·채권이 동시에 움직여 포트폴리오 전체 영향을 빠르게 집계해야 했다.

### 왜 단순 LLM으로는 안 되는가

- 챗봇에 "관세 25%면 포트폴리오 손익은?"이라고 물으면 **그럴듯한 숫자**를 만든다. 근거도, 재현도, 검증도 없다.
- 필요한 것은 (1) 출처 있는 데이터 조회, (2) 결정론적 계산, (3) 추론과 계산을 분리하고 검증하는 구조다. 이것이 Agent가 필요한 이유다.

### 해결할 문제 (범위)

| 포함 | 제외 (MVP 밖) |
| --- | --- |
| 관세·금리·규제 유형의 정책 발표 | 기업 개별 공시, 실적 |
| 거시 팩터 7개(원/달러, KOSPI, KOSPI IT, 미국 주식 대리, 미 국채 10년, 국고채 3년, WTI) | 개별 종목 모델 |
| 가상 모델 포트폴리오 2개(자산배분형 A, 채권형 B) | 실제 보유내역 연동 |
| 20영업일 단기 파급 | 장기 밸류에이션 |

시각 자료: 현재 업무 흐름(5단계, 반나절) vs RIPPLE(1분) 비교 그림.

## 3. 서비스 제안

### 사용 흐름

```
① 이벤트 대시보드        ② 새 분석              ③ 분석 워크스페이스                 ⑤ 계산 근거 패널
오늘 수집된 정책 발표  →  입구 선택·포트폴리오 →  실행 과정(실시간) · 파급 경로 ·  →  수식 · 입력값 ·
카드에서 '분석하기'       선택 · '분석 시작'       시나리오(수정→재계산) · 결과 ·      출처 · 수집일 ·
                                                   보고서(PDF)                          계산 ID
```

두 가지 입구: **정책 이벤트로 시작**(7단계) / **시나리오 직접 입력**("유가 30% 급등 + 원화 10% 약세", 5단계).

### 사용자가 얻는 것

| 결과물 | 내용 |
| --- | --- |
| 파급 경로 그래프 | 정책 → 산업 → 거시 변수 → 자산군 4열 노드-엣지. 엣지에 방향(+/−)과 확신도(실선/점선). 노드 클릭 → 근거 목록(출처·수집일) |
| 시나리오 표 | 변수별 충격값·단위·근거·과거 최대 변동폭 대비 위치. 값을 직접 고치고 **재계산** |
| 손익 결과 | 포트폴리오 예상 손익(%·금액)과 95% 추정 범위, 자산별 손익 막대, 손실 기여 상위 5, **팩터 모델 vs 과거 유사 국면** 두 추정치 병렬, 유사 국면 5구간(기간·유사도·당시 실제 손익) |
| 헤지 제안 | 규칙 기반: 환율 기여 ≥30% → 환헤지 상향, 단일 업종 ≥40% → 비중 축소, 금리 기여 큼 → 듀레이션 조정 |
| 보고서 | 요약·경로·손익·헤지·데이터 출처 5개 섹션. Markdown/PDF. 모든 수치가 계산 로그에 연결 |
| 실행 과정 | Agent 7단계 타임라인: 상태(대기/실행 중/완료/반려·재시도/실패), 소요 시간, 입력·출력 요약, 모델·토큰 |

### 설계 원칙 (화면에 그대로 드러난다)

1. **숫자는 모두 근거로 이어진다.** 화면의 모든 수치는 클릭 가능하고 계산 근거 패널이 열린다. (심사 항목 "결과의 신뢰성")
2. **Agent가 일하는 모습이 보인다.** 단계별 진행·반려 루프를 실시간으로 보여준다. ("AI Agent 기술성")
3. **가상 포트폴리오임을 상시 표시**하고, 합성 데이터로 돌아갈 때는 상단에 경고 배지를 띄운다.

### 기존 대안과 비교

| | 스프레드시트 수작업 | 범용 LLM 챗봇 | 상용 리스크 시스템 | RIPPLE |
| --- | --- | --- | --- | --- |
| 정책 발표 → 경로 추론 | 사람 | 가능(근거 없음) | 없음 | Agent + 근거 검증 |
| 손익 계산 | 가능 | **환각 위험** | 가능 | 격리된 엔진만 |
| 근거 추적 | 메모 | 없음 | 제한적 | 수치당 계산 로그 |
| 소요 | 반나절 | 1분(신뢰 불가) | 설정 필요 | 1분 |

시각 자료: 화면 S1·S3 캡처, 계산 근거 패널 캡처.

## 4. AI Agent 구성

### 아키텍처

```
프론트엔드(Vue 3)  ──REST/SSE──▶  API(FastAPI)  ──▶  LangGraph Orchestrator (공유 상태 RunState)
                                                      ├─ Event Analyst      (LLM 구조화)
                                                      ├─ Impact Mapper      (LLM 추론 + 통계 도구)
                                                      ├─ Scenario Builder   (LLM + 과거 변동 통계)
                                                      ├─ Regime Finder      (Python 계산)
                                                      ├─ Risk Engine        (격리된 Python 계산 → calc_log)
                                                      ├─ Validator          (규칙 검사 → 반려)
                                                      └─ Report Writer      (LLM 문장 + 엔진 치환)
                                   저장소: PostgreSQL 9개 테이블 (시계열·이벤트·포트폴리오·베타·실행·단계 로그·계산 로그)
                                   LLM: Claude Haiku 5.5 (기본) · Sonnet 5.5 (본선 Impact Mapper)
```

### Agent별 역할·도구·실패 처리

| Agent | 입력 → 출력 | 도구 | 자율성·실패 처리 |
| --- | --- | --- | --- |
| Orchestrator | 사용자 입력 → 실행 계획 | LangGraph 조건부 라우팅 | 입구별 진입점, 반려 시 되돌림, 재시도 상한 초과 시 부분 결과+경고 |
| Event Analyst | 발표 원문 → `event`(국가·유형·대상·수치) | 수집기, LLM 구조화 출력(JSON 스키마) | 필수 필드 누락 시 표시·사용자 확인 |
| Impact Mapper | `event` → `impact_paths`(≤3경로, ≤4단계) | 과거 사례 통계·무역/거시 요약 조회, LLM 추론 | 정량 근거 없는 단계는 `low`. Validator 반려 시 사유를 받아 재추론(≤2회) |
| Scenario Builder | 경로 또는 자연어 → `scenario`(팩터별 충격값) | 과거 변동성 통계, 자연어 파서 | 과거 최대 변동폭 초과 시 경고 |
| Regime Finder | `scenario` → `regimes`(상위 5구간) | 시계열 유사도 계산(코사인·표준화) | 유사 구간 없으면 팩터 모델만 사용 |
| Risk Engine | `scenario`·포트폴리오·`regimes` → `result`+`calc_log` | OLS 베타, 충격 적용, 표준오차 범위, 유사 국면 실제 손익, 헤지 규칙 | 오류 시 1회 재실행 후 실패 보고 |
| Validator | 전체 상태 → `validation` | 규칙 4개(근거·형식·수치 일관성·보고서 인용) | 실패 항목별 담당 Agent에 **반려** |
| Report Writer | 전체 상태 → `report` | 템플릿, `{{키}}` 치환 | 수치는 계산 로그 키로만 인용. 마커 밖 숫자는 제거+경고 |

### 실행 흐름과 자율성

- `entry=event`: EA → IM → SB → RF → RE → VA → RW. `entry=scenario`: SB부터. 충격값 수정: RF부터(앞 단계 결과 재사용).
- **반려 루프**: Validator가 "확신도 high인데 근거 2건 미만" 같은 위반을 찾으면 Impact Mapper에 사유를 넘기고 재실행. 상한(Impact Mapper 2회, Risk Engine 1회)을 넘으면 부분 결과와 경고로 종료 — 무한 루프 없음.
- 모든 단계의 입력·출력·소요 시간·모델·토큰을 `agent_step`에 기록 → 화면 타임라인과 운영진 검증 요청에 그대로 사용.

### 환각·오류 대응 (결과의 신뢰성)

| 위험 | 대응 |
| --- | --- |
| LLM이 숫자를 지어냄 | 계산은 엔진만. 보고서는 자리표시자만 허용, 엔진이 치환. Validator가 마커 밖 숫자를 찾아 문장 제거 |
| LLM 출력 형식 오류 | JSON 스키마(Pydantic) 검증 통과한 것만 상태 반영 |
| 근거 없는 추론 | 근거 수로 확신도 상한(high ≥2건, mid ≥1건). 위반 시 반려 |
| 미래 데이터 누출 | 과거 재현 시 결정일 이후 데이터 차단(시점 필터) |
| 결과 재현 불가 | 계산 로그에 입력·출력·코드 해시·엔진 버전 기록, 계산 ID 발급 |
| 모델 거부/한도 초과 | 단계 실패로 기록, 실행을 실패로 종료(조용히 넘어가지 않음) |

### LLM 모델 전략과 비용

| 구간 | 모델 | 설정 |
| --- | --- | --- |
| 개발·예선 | 전 단계 Claude Haiku 5.5 | `MODEL_DEFAULT=claude-haiku-5-5` |
| 본선 튜닝 | Impact Mapper만 Claude Sonnet 5.5 | `MODEL_IMPACT_MAPPER=claude-sonnet-5-5` |

프롬프트에는 시계열 원본 대신 **요약 통계**만 넣어 분석 1회 약 2만 토큰(수 원). 데모 시나리오 결과는 캐시해 심사 기간 비용·장애를 막는다. 키가 없으면 `offline` 모드(규칙 기반 Agent)로도 전 흐름이 동작한다.

시각 자료: LangGraph 그래프 그림(노드 7개 + 반려 엣지), 타임라인 화면 캡처(반려 화살표 포함).

## 5. 데이터 활용 계획

### 데이터 소스

| 수집기 | 데이터 | 출처 | 사용 원칙 |
| --- | --- | --- | --- |
| `fred.py` | 미 국채 10년(DGS10), WTI(DCOILWTICO) | FRED API | 공개 데이터. **S&P 500 등 제3자 저작권 지수는 수집하지 않음** |

| `krx_prices.py` | KOSPI, KOSPI 200, 업종지수, 국내 상장 해외지수·섹터 ETF 시세 | 공공데이터포털 금융위원회 시세정보 API | 이용허락범위 확인한 API만. 해외 주식 노출은 **국내 상장 ETF로 대체** |
| `federal_register.py` | 미국 관보(관세·규제 고시) | Federal Register API | 키 불필요. 관보 로고·인장 사용 금지 |
| `korea_briefing.py` | 한국 정부 보도자료 | 대한민국 정책브리핑 | 공공누리 유형 표시된 자료만, 유형별 출처 표시 |
| (확장) | 품목별 수출입 실적 | 공공데이터포털 관세청 API | 위와 동일 |

본 대회는 데이터셋을 제공하지 않으므로 전부 공개 API를 직접 수집한다. 하루 1회 배치, 5년치 일별 시계열.

### 출처·수집일·라이선스·전처리 기록 (제출물 기재 의무)

- 모든 값에 `collected_at`, 모든 시리즈에 `source`·`license`·`source_url` → 화면의 계산 근거 패널과 보고서 "데이터 출처" 섹션에 자동 표기. `data/SOURCES.md`에 같은 내용.
- 전처리: 결측(".") 제거, 영업일 기준 정렬, 팩터 변환(지수·환율·유가는 변화율 %, 금리는 차분 %p), 자산 수익률은 USD 기준(원화 자산은 환율 환산), 채권은 듀레이션 근사.
- **데이터 관리 화면(S7)** 에서 시리즈별 출처·라이선스·기간·건수·최종 수집 시각, 수집기 실행 결과, 다음 예약 수집을 누구나 확인할 수 있다 — 제출물의 "출처·수집일·라이선스 기재"가 화면 자체에 들어 있다.
- 수집은 서버가 하루 1회 자동 실행(실패·미완료 시 2시간마다 재시도)하고, 외국어 관보 이벤트는 수집 직후 Claude가 한국어 제목·요약·유형·수치·포트폴리오 관련성으로 구조화한다(원문 제목 보존).
- 현재 적재 상태(2026-10-14): FRED(미 국채 10년·WTI) 2,745일, 한국은행 ECOS(원/달러·국고채 3년) 2,705일, 금융위원회 시세(KOSPI·KOSPI 200·ETF 4종) 1,662일, Federal Register 관세·규제 문서 321건 — 전부 실데이터. 실데이터 적재 전에는 합성 시계열(source=SYNTHETIC)로 데모하며 화면에 경고 배지를 띄운다.

### 계산 로직

① **팩터 민감도**: 자산 i의 일별 수익률을 팩터 수익률에 OLS 회귀(최근 3~5년) → β, 표준오차, R².
   r_{i,t} = α_i + Σ_k β_{i,k} f_{k,t} + ε_{i,t}

② **충격 적용**: ΔR_i = Σ_k β_{i,k} Δf_k, ΔP = Σ_i w_i ΔR_i. 손실 기여도 = w_i × ΔR_i 상위 5. 표준오차로 95% 범위.

③ **과거 유사 국면**: horizon(20영업일) 구간의 팩터 변화 벡터를 표준화해 시나리오 벡터와 코사인 유사도(크기 가중) → 상위 5개 비중복 구간 → 각 구간에서 포트폴리오에 실제로 일어났을 손익을 재계산해 팩터 모델 추정과 나란히 제시.

④ **헤지 규칙**: 환율 기여 ≥30%, 단일 업종 ≥40%, 금리 기여 ≥25%(설정 가능). 제안 문장은 규칙 결과로만.

### 가상 포트폴리오

실제 기관 보유내역이 아닌 **가상 모델 포트폴리오** 2개(자산배분형 A: 국내 반도체·KOSPI 200·국고채·미국 주식·미 국채·원유 등 8종목, 채권형 B: 6종목)를 `data/portfolios.json`에 정의하고 화면에 상시 배지로 표시한다.

시각 자료: 데이터 흐름도(수집기 → series/policy_event → 엔진 → calc_log → 화면), 계산 근거 패널 캡처.

| 재현성 | 사람마다 다름 | 같은 입력 → 같은 계산 ID·코드 해시 | 계산 로그 |
| 과거 사례 재현도 | — | 방향 적중률·크기 오차 (2019 일본 수출규제, 2025 미국 상호관세) | `scripts/backtest.py`, 결정일 이후 데이터 차단 |

### 정성 효과

- **리스크·리서치·운용의 공통 언어**: 같은 경로 그래프와 계산 근거를 보고 논의한다.
- **검토 가능한 AI**: Agent 판단과 계산을 분리하고 반려 기록을 남겨, 감사·내부통제 관점에서 설명 가능하다.
- **학습 자산**: 실행 이력이 쌓이면 "어떤 유형의 발표가 어떤 경로로 얼마나" 데이터가 된다.

### 확장성

| 방향 | 방법 |
| --- | --- |
| 실제 포트폴리오 | `portfolio`·`holding` 테이블에 보유내역 연동, 통화·업종 자동 분류 |

국부펀드·연기금처럼 정책 변수에 노출이 큰 기관이 **정책 발표 당일** 영향을 투명한 근거와 함께 파악하게 한다. 공개 데이터와 출처 표기 원칙만으로 구현해 다른 기관도 그대로 쓸 수 있다.
